## 4. 三条红灯的成因与正确修法

> **2026-11-22 晚已修复**：`PeriodRepository` 增加可注入时钟（`now:`），测试把"今天"锁在
> 2026-11-21；`today_widget_test` 的包名与 Kotlin 路径改到 `com.yueji.note`。
> 现状：`flutter test` → **275 通过 / 1 跳过**（跳过的是图标生成器，需 `GEN_ICONS=1` 才执行）。
> 以下保留原始分析，供后续遇到同类问题参考。

> 都在 test/ 下，**不是产品代码回归**。按 AGENTS R4「一个任务一个提交」拆两次提交。

### 4.1 `test/period/period_history_repository_test.dart`（2 条）

```
删除历史经期 → 期望 cycleLength 56，实际 57
端到端预测     → 期望 everyElement(28)，实际 [28, 29]
```

成因：`setUp` 用 `repo.startPeriod(DateTime.now())` 造"今天"这段，但断言把日期**写死成 11/21**（9/26→11/21=56、10/24→11/21=28）。今天是 11/22，于是 57 与 29。**这类测试会随时间每天再红一次**，不是偶发。

修法（二选一，建议 A）：

- A. `PeriodRepository` 注入时钟：`PeriodRepository(db, {DateTime Function()? now})`，默认 `DateTime.now`；`PeriodHistoryEditor.upsert/remove` 已支持 `today` 参数，一并透传。测试固定 `now: () => DateTime(2026, 11, 21)`。
- B. 测试内把基线改成相对现在构造（`startPeriod(now)` 后按 `now.difference(9/26).inDays` 断言），但会失去"人为规定日期"的可读性。

**不要**只把期望值改成 57/29 —— 那是把 bug 固化进断言（AGENTS §7 明确禁止）。

### 4.2 `test/weight_loss/today_widget_test.dart`（1 条）

```
缺文件：android/app/src/main/kotlin/com/example/cycle_note/HomeWidgetProvider.kt
```

成因：P6 把包名迁到 `com.yueji.note`，真实文件在 `.../kotlin/com/yueji/note/HomeWidgetProvider.kt`，但测试里的**路径与 `package` 断言**没跟着改（全仓仅此 2 处残留，已 grep 确认）。

修法：改这两处字符串即可（测试自身缺陷）。

4. **灰度反馈回来再动 §7**：A 组（界面补齐）优先于 C/D，因为灰度用户最先抱怨的通常是"今天页看不到我吃了什么"。

## 9. 接手时需要知道的三个坑（环境类，与代码无关）

1. **构建必须在无沙箱审计的环境跑**：沙箱内 java 逐文件 IO 被审计，`transforms/*.lock` 抢锁 → Gradle 必失败。且 `GRADLE_USER_HOME` 建议固定 `$env:GRADLE_USER_HOME`（3314 MB，已预热）。
2. **`flutter build` 报 `Unable to determine engine version`** → 删 `<flutter-sdk>\bin\cache\engine.stamp`，让 `flutter --version` 重新生成。
3. **adb 在命令结束后被环境回收** → 等待/安装/截图必须压进一条命令；Git Bash 会把 `/sdcard/...` 转成 Windows 路径，截图用 `exec-out screencap -p > file`。脚本：`_tools/adb_pipeline.sh`。
