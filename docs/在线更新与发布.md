# 月记 · 在线更新与发布（纯 GitHub 通道）

> 2026-11 起：App **完全脱钩自建服务器**，所有更新产物只发 GitHub。
> 不存在 NAS、FRP、自建镜像等第二条链路。

## 1. 用户侧的更新流程

```
用户点「我的 → 检查更新」
        │
        ├─ ① GitHub raw 拉 update/latest.json（超时 5 秒）
        │      ↓ 版本比当前新
        │   用 manifest 里的 apkUrl 下载 APK
        │      ↓
        │   校验 sha256 → 拉起系统安装器
        │
        └─ ② ①失败（超时 / 4xx / JSON 坏）
              改拉 jsDelivr 镜像的同一份 latest.json（超时 8 秒）
                 ↓
              同样走 apkUrl 下载（GitHub Release 地址）
```

**两条通道的内容来源都是 GitHub**：

| 通道 | manifest 来源 | APK 来源 |
|---|---|---|
| GitHub（主） | `raw.githubusercontent.com` | GitHub Release |
| jsDelivr（镜像） | `cdn.jsdelivr.net/gh/...` | 同上（Release 地址） |

jsDelivr 只是对同一仓库的 CDN 加速，**不是第二份产物**，版本和 sha256 完全一致。

## 2. 需要你填的占位符

只有一个文件：`lib/features/update/update_config.dart`

```dart
// 主通道：GitHub raw
kUpdateUrlGitHub  = 'https://raw.githubusercontent.com/<OWNER>/<REPO>/main/update/latest.json'

// 镜像通道：jsDelivr（内容同源，只是 CDN 不同）
kUpdateUrlMirror  = 'https://cdn.jsdelivr.net/gh/<OWNER>/<REPO>@main/update/latest.json'
```

当前已填为 `Charon-1978/cycle_note`。换仓库时只改这两行。

## 3. manifest 结构

`update/latest.json`：

```json
{
  "version": "1.1.0",
  "notes": "本次更新说明（纯文本，按行显示）",
  "apkUrl": "https://github.com/<OWNER>/<REPO>/releases/download/v1.1.0/yueji-1.1.0-arm64.apk",
  "sha256": "小写十六进制 64 位",
  "size": 31970341,
  "publishedAt": "2026-11-22T14:54:30Z"
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | ✅ | 语义化版本，带不带 `v` 都行；比较时归一化 |
| `apkUrl` | ✅ | 必须 http(s) |
| `notes` | ⬜ | 更新说明 |
| `sha256` | ⬜ | 64 位小写；缺失则不校验 |
| `size` | ⬜ | 字节数；缺失时按下载流统计 |
| `publishedAt` | ⬜ | ISO 8601 |
| `fallbackApkUrl` | ⬜ | **本项目不用**（APK 只在 Release，单地址足够） |

解析失败会抛 `UpdateManifestException`，调用方据此切换通道，**不会把坏数据当成「已是最新」**。

## 4. 发布一条新版本

### 方式 A：CI 自动（推荐）

```bash
# 1) 改 pubspec.yaml 的 version
# 2) 提交
git add -A && git commit -m "chore(release): 1.1.1"

# 3) 打 tag 并推送（会触发 .github/workflows/release.yml）
git tag v1.1.1
git push origin main --tags
```

CI 会：

1. 用 Secrets 里的 keystore 签名
2. 构建 `yueji-1.1.1-arm64.apk`
3. 算 sha256
4. 发 GitHub Release
5. 更新 `update/latest.json` 并推回 main

### 方式 B：本机手动

```powershell
# 1) 构建 + 算 hash + 写 latest.json
powershell -ExecutionPolicy Bypass -File _tools\publish_update.ps1 `
    -Version 1.1.1 -Notes "修复补记日期限制" `
    -GitHubRepo "Charon-1978/cycle_note"

# 2) 上传到 Release（脚本会打印 gh 命令）
gh release create v1.1.1 dist\yueji-1.1.1-arm64.apk `
    --title "月记 v1.1.1" --notes "修复补记日期限制"

# 3) 提交清单
git add update/latest.json pubspec.yaml
git commit -m "chore(release): 1.1.1"
git push
```

## 5. CI 需要配的 Secrets

仓库 → Settings → Secrets and variables → Actions：

| Secret | 必填 | 说明 |
|---|---|---|
| `KEYSTORE_BASE64` | ✅ | release keystore 的 base64：`base64 -w0 key.jks` |
| `KEYSTORE_PASSWORD` | ✅ | keystore 密码 |
| `KEY_ALIAS` | ✅ | 密钥别名 |
| `KEY_PASSWORD` | ✅ | 密钥密码 |

没配 Secrets 时会用 debug 签名（仅供自测，**不要发布**）。

## 6. 首次托管到 GitHub

```bash
git init
git add -A
git commit -m "init"

# 建远程仓库后
git remote add origin https://github.com/Charon-1978/cycle_note.git
git branch -M main
git push -u origin main
```

**注意**：`.githooks/pre-commit` 会在提交前跑隐私审计（`_tools/privacy_audit.py`），
发现密钥或敏感文件会**阻断提交**。临时跳过用 `git commit --no-verify`。

## 7. 验证方法

```bash
# manifest 是否可达
curl -s https://raw.githubusercontent.com/Charon-1978/cycle_note/main/update/latest.json

# 镜像是否一致
curl -s https://cdn.jsdelivr.net/gh/Charon-1978/cycle_note@main/update/latest.json

# APK 是否可下（取前 1MB）
curl -s -r 0-1048575 -o /dev/null -w "%{http_code} %{size_download}\n" \
  https://github.com/Charon-1978/cycle_note/releases/download/v1.1.0/yueji-1.1.0-arm64.apk

# sha256 是否一致
sha256sum yueji-1.1.0-arm64.apk
# 对比 manifest 里的 sha256 字段
```

## 8. 常见问题

**Q：国内访问 raw.githubusercontent.com 不通怎么办？**

A：manifest 会自动走 jsDelivr 镜像。但 **APK 仍从 GitHub Release 下载**——
如果 Release 也不通，可以配代理，或临时用 `ghproxy` 类镜像手动下载后侧载。
App 不做这类兜底，避免引入第三方不可控节点。

**Q：为什么不用自建服务器做兜底？**

A：多一条链路就多一份维护成本和泄露面（服务器地址、端口、证书）。
GitHub 单点足够：Release 由 Microsoft 基础设施托管，可用性高于个人 NAS。

**Q：jsDelivr 上的 dist/ 为什么取不到 APK？**

A：`dist/` 被 `.gitignore` 排除（APK 30MB，不进 Git）。jsDelivr 只能分发仓库内文件，
所以 APK 只走 GitHub Release。
