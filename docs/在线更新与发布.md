# 月记 · 在线更新与发布（GitHub + NASHub 双通道）

> 2026-11-22 · 对应版本 v1.1.0
> 相关代码：`lib/features/update/`，原生侧 `MainActivity.kt`，清单 `AndroidManifest.xml`

---

## 1. 用户侧的更新流程

1. 「我的」→「检查更新」（`/me/update`）；
2. 点「检查更新」→ **先请求 GitHub** 的 `latest.json`：
   - 5 秒超时 / 非 200 / JSON 坏 → **自动改请求 NASHub**（12 秒超时）；
3. 若远端版本 > 当前版本 → 显示版本号、更新说明、来源（GitHub / NASHub）；
4. 点「下载安装包」→ 先下 `apkUrl`（GitHub Release），失败（404/超时/**sha256 不符**）→ 换 `fallbackApkUrl`（NASHub）；
5. 下载完成点「安装」→ 没有「安装未知来源应用」权限时，先跳系统设置页；
6. 安装交给系统安装器（FileProvider 授权），App 自己不申请任何特殊权限。

**隐私边界**：只在用户点按钮时联网；只访问 `update_config.dart` 里配置的两个域名；不上报任何健康数据。

## 2. 需要你填的三个占位符

| 位置 | 占位符 | 填什么 |
|---|---|---|
| `lib/features/update/update_config.dart` | `YOUR_GITHUB/cycle_note` | GitHub 仓库（owner/repo），或构建时用 `--dart-define=UPDATE_URL_GITHUB=...` 覆盖 |
| 同上 | `YOUR_NAS_DOMAIN` | NASHub 的公网域名，`--dart-define=UPDATE_URL_NAS=...` 可覆盖 |
| `_tools/publish_update.ps1` | 参数 `-GitHubRepo` / `-NasDir` / `-NasBaseUrl` | 发布时传参即可 |

> 三个值都支持**不改代码**切换：`flutter build apk --dart-define=UPDATE_URL_GITHUB=https://... --dart-define=UPDATE_URL_NAS=https://...`

## 3. manifest 结构（两条通道用同一份）

`update/latest.json`（GitHub 上通过 raw 访问）：

```json
{
  "version": "1.1.0",
  "notes": "新增在线更新；补记流程重构",
  "apkUrl": "https://github.com/OWNER/REPO/releases/download/v1.1.0/yueji-1.1.0-arm64.apk",
  "fallbackApkUrl": "https://NAS_DOMAIN/nashub/yueji/yueji-1.1.0-arm64.apk",
  "sha256": "…64 位小写十六进制…",
  "size": 31707405,
  "publishedAt": "2026-11-22T10:00:00Z"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | ✅ | 语义化版本，`v` 前缀会被自动去掉；与 `pubspec.yaml` 的 `version:` 前段必须一致（有测试兜底） |
| `apkUrl` | ✅ | 必须是 http(s)；GitHub 通道 |
| `fallbackApkUrl` | ⬜ | NASHub 镜像地址 |
| `notes` | ⬜ | 纯文本，按行显示 |
| `sha256` | ⬜ | 有则校验，不符自动换下一个地址 |
| `size` | ⬜ | 下载进度用；缺失时用 `Content-Length` |
| `publishedAt` | ⬜ | ISO8601 |

## 4. NASHub 侧怎么放

NASHub 只当**静态文件服务**用，目录结构固定：

```
<nas>/nashub/yueji/
├── latest.json          ← 与 update/latest.json 同一份（可指向同一 APK）
├── yueji-1.1.0-arm64.apk
└── yueji-1.1.0-arm64.apk.sha256   （可选，方便人工核对）
```

对应公网地址：

```
https://NAS_DOMAIN/nashub/yueji/latest.json
https://NAS_DOMAIN/nashub/yueji/yueji-1.1.0-arm64.apk
```

如果用 NAS 的应用中心（NASHub）做分发，只要**能提供上面两个 URL**即可；不能自定义路径时，
把 `UPDATE_URL_NAS` 指到实际路径就行，App 侧不用改。

## 5. 发布一条新版本（本机一键）

```powershell
# 1) 构建 + 算 hash + 写 latest.json + 拷到 NAS 挂载盘
powershell -ExecutionPolicy Bypass -File _tools/publish_update.ps1 `
    -Version 1.1.1 -Notes "修复 xxx" `
    -NasDir "Z:\nashub\yueji" `
    -GitHubRepo "yourname/cycle_note" `
    -NasBaseUrl "https://nas.example.com/nashub/yueji"

# 2) 发 GitHub Release（脚本会打印这条命令）
gh release create v1.1.1 "<repo>\dist\yueji-1.1.1-arm64.apk" --title "v1.1.1" --notes "修复 xxx"

# 3) 提交版本号与清单
git add update/latest.json pubspec.yaml lib/features/update/update_config.dart
git commit -m "chore(release): v1.1.1" && git push
```

**或者交给 CI**：`git tag v1.1.1 && git push origin v1.1.1` → `.github/workflows/release.yml` 自动
构建、发 Release、回写 `update/latest.json`（需要配好 keystore secrets，见工作流注释）。

## 6. 首次托管到 GitHub 的步骤

```powershell
# 仓库初始化（如果还没做）
cd <repo>
git init -b main
git add .
git commit -m "feat: 月记 v1.1.0"
gh repo create cycle_note --private --source . --push
# 或：git remote add origin git@github.com:yourname/cycle_note.git && git push -u origin main
```

注意（本仓库体积）：
- `dist/`、`build/`、`_shots_new/` 已在 `.gitignore` 里，别把 30MB 的 APK 提交进 Git；
- APK 只挂在 **Release** 上，raw 只放 `update/latest.json`（几 KB）。

## 7. 验证方法

1. 把 `latest.json` 的 `version` 改成比当前高（如 `9.9.9`），`apkUrl` 指向真实 APK；
2. 装机 → 「我的」→「检查更新」→ 应显示「发现新版本 v9.9.9 · 来源 GitHub」；
3. 断开 GitHub（改 `UPDATE_URL_GITHUB` 为不可达地址重新构建）→ 应显示「来源 NASHub」；
4. 故意写错 `sha256` → 下载应自动切换兜底地址，日志里能看到「sha256 不匹配」。

单元测试（`test/update/`）已覆盖：版本比较、manifest 校验、GitHub 失败切 NASHub、
下载失败切兜底、sha256 不符切兜底、版本号与 pubspec 同步。
